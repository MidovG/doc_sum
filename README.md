# docsum — общее саммари по содержимому папки

Программа берёт папку с документами (локальную, ZIP или публичную папку Google Drive),
извлекает текст из всех файлов и с помощью LLM строит **общее саммари по всей информации внутри**
плюс краткие саммари по каждому документу.

## Быстрый старт

```bash
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -e .                                       # + ".[anthropic]" для Claude, ".[dev]" для тестов

# Tesseract OCR — для картинок и сканов (необязательно, но без него они пропускаются)
brew install tesseract tesseract-lang                  # macOS; Ubuntu: apt install tesseract-ocr tesseract-ocr-rus

# OpenAI
export OPENAI_API_KEY=sk-...
docsum "https://drive.google.com/drive/folders/1x6EKNkVw6PlFVTr6cGrsVscmRuwqGrXd?usp=sharing"

# Локально через Ollama (без интернета и ключей) — подробнее ниже
ollama pull qwen2.5:7b
docsum ./docs --provider ollama --model qwen2.5:7b --num-ctx 16384

# Claude
export ANTHROPIC_API_KEY=...
docsum ./docs --provider anthropic

# Любой OpenAI-совместимый API (vLLM, LM Studio, OpenRouter, DeepSeek…)
docsum ./docs --provider openai --base-url http://localhost:8000/v1 --model my-model
```

Результат — `summary.md` (общее саммари → саммари по документам → список необработанных файлов)
и, с флагом `--json out.json`, то же самое в JSON. Итоговое саммари также печатается в консоль.

Без установки пакета: `python -m docsum <источник> [опции]`.
Настройки можно положить в `.env` (`OPENAI_API_KEY`, `DOCSUM_PROVIDER`, `DOCSUM_MODEL`, `OLLAMA_HOST`,
`TESSERACT_CMD`, …).

## Как это работает

```
источник ──► загрузка ──► извлечение текста ──► OCR картинок ──► нарезка ──► MAP: саммари фрагментов
(Drive/папка/ZIP) (gdown)   (по формату)       и сканов PDF     (по абзацам)        │
                                               (Tesseract)                          ▼
               summary.md ◄── FINAL: общее саммари ◄── REDUCE: саммари документов
```

1. **Загрузка.** Ссылка на Drive скачивается через `gdown` (Google Docs/Sheets/Slides экспортируются
   в docx/xlsx/pptx). Локальный путь используется как есть, обход рекурсивный.
2. **Извлечение текста**: PDF (PyMuPDF, с номерами страниц), DOCX (абзацы и таблицы в исходном порядке),
   XLSX (все листы), PPTX (слайды, таблицы, заметки), TXT/MD/CSV/JSON/HTML/XML/RTF/EML, ZIP (рекурсивно).
   Кодировки txt определяются автоматически (utf-8 / cp1251 / koi8-r). Служебный мусор (`~$*`, `__MACOSX`)
   пропускается. Один битый файл не ломает прогон — он попадает в раздел «Не обработаны» с причиной.
   **Изображения** (PNG, JPG, GIF, BMP, WebP, многостраничный TIFF) и **страницы-сканы PDF** (без
   текстового слоя) распознаются Tesseract OCR — подробнее в разделе ниже.
3. **Map-reduce.** Короткий документ суммаризируется одним запросом. Длинный режется на фрагменты
   (`--chunk-chars`, по границам абзацев, с перекрытием), фрагменты суммаризируются параллельно,
   затем объединяются в саммари документа.
4. **Общее саммари** строится по саммари всех документов. Если они не влезают в контекст модели
   (`--context-chars`), включается иерархическое сжатие группами — так программа работает с папкой
   любого размера и с моделями с маленьким контекстом.

Промпты требуют опираться только на текст и сохранять конкретику (стороны, даты, суммы, сроки,
обязательства). Итог структурирован: общая картина, ключевые выводы, важные факты с указанием
документа-источника, противоречия и пробелы между документами, состав папки.

**Надёжность и стоимость:** повторы с экспоненциальной задержкой на 429/5xx и сетевых ошибках;
общий лимит параллельных запросов (`--workers`); дисковый кэш ответов LLM (`.docsum_cache/`) —
повторный запуск после сбоя или правки промпта не оплачивает уже сделанные запросы;
вырезание `<think>…</think>` у reasoning-моделей (qwen3, deepseek-r1).

## Локальная модель через Ollama

```bash
ollama pull qwen2.5:7b                       # или qwen3:8b, gemma3:12b и т.п.
docsum ./docs --provider ollama --model qwen2.5:7b --num-ctx 16384
```

Ollama на другой машине: `--base-url http://192.168.1.10:11434` (или переменная `OLLAMA_HOST`).

**Почему важен `--num-ctx`.** Ollama по умолчанию держит контекст в несколько тысяч токенов
и **молча обрезает** всё, что не влезло: модель видит только кусок документа, а саммари выглядит
правдоподобно. Поэтому программа ходит в родной API Ollama (`/api/chat`), а не в OpenAI-совместимый
`/v1`, и передаёт `num_ctx` в каждом запросе. Под этот контекст автоматически подбираются размер
фрагмента и объём текста на объединение (из расчёта ~2,5 символа кириллицы на токен), так что
вход + ответ модели всегда влезают. Если сервер всё же сообщит, что промпт упёрся в лимит, в логе
будет предупреждение.

| `--num-ctx` | Фрагмент / объединение | Память для qwen2.5:7b (Q4), примерно |
|---|---|---|
| 8192 | 12 000 / ~14 000 симв. | ~5,5 ГБ |
| 16384 (по умолчанию) | 12 000 / ~34 000 симв. | ~6 ГБ |
| 32768 | 12 000 / ~75 000 симв. | ~7 ГБ |

Больше контекст — меньше уровней сжатия и лучше связность итогового саммари, но больше памяти
и медленнее; у моделей без GQA (и у крупных) память на контекст растёт заметно быстрее. Если модель не влезает в видеопамять — уменьшайте `--num-ctx` или берите модель меньше.

Что ещё делается для локального запуска:
- перед стартом проверяется, что Ollama запущена и модель скачана, — иначе понятная ошибка
  с командой `ollama pull …`, а не падение посреди обработки;
- запросы идут по одному (`--workers 1`): Ollama и так обрабатывает их к одной модели по очереди,
  а параллельные слоты умножают расход памяти на контекст. Если запущен с `OLLAMA_NUM_PARALLEL=2`,
  можно поставить `--workers 2`;
- рассуждения reasoning-моделей (`<think>…</think>` у qwen3, deepseek-r1) вырезаются из ответа;
- таймаут на запрос — 30 минут (на CPU большие фрагменты считаются долго);
- HTTP-прокси из переменных окружения для Ollama игнорируется, чтобы корпоративный прокси
  не перехватывал запросы к локальному серверу.

## Изображения и сканы (Tesseract OCR)

```bash
brew install tesseract tesseract-lang          # macOS (tesseract-lang — в том числе русский)
sudo apt install tesseract-ocr tesseract-ocr-rus   # Ubuntu/Debian
# Windows: https://github.com/UB-Mannheim/tesseract/wiki — в установщике отметить Russian
```

Дальше ничего настраивать не нужно: программа сама находит Tesseract (в `PATH`, в стандартной
папке установки на Windows или по переменной `TESSERACT_CMD`) и распознаёт:
- отдельные изображения — PNG, JPG, GIF, BMP, WebP, TIFF (многостраничный — постранично);
- страницы PDF без текстового слоя (сканы). Текстовые страницы того же PDF читаются как обычно,
  порядок страниц сохраняется.

Как устроено распознавание:
- страницы-сканы рендерятся в 300 dpi; изображения переводятся в оттенки серого, мелкие
  увеличиваются, контраст выравнивается — так Tesseract ошибается заметно реже;
- считается средняя уверенность распознавания. Если она низкая, программа предполагает, что
  скан повёрнут: пробует угол, который подсказал Tesseract (OSD), а затем остальные повороты
  и оставляет лучший вариант;
- текст с низкой уверенностью (< 45%) попадает к модели с пометкой «низкое качество, возможны
  ошибки», чтобы она не выдавала мусор OCR за факты; картинки без текста (фото, рисунки) отбрасываются;
- изображения распознаются параллельно по числу ядер процессора;
- в отчёте у каждого такого документа указано, сколько изображений распознано и с какой уверенностью.

Языки — `--ocr-lang` (по умолчанию `rus+eng`). Если какого-то языкового пакета нет, программа
предупредит и распознает на доступных. Если Tesseract не установлен, изображения не ломают прогон:
они попадают в раздел «Не обработаны» с инструкцией по установке. Выключить OCR — `--no-ocr`.

## Опции

| Опция | По умолчанию | Назначение |
|---|---|---|
| `--provider` | `openai` | `openai`, `ollama`, `anthropic`, `fake` (без сети, для проверки) |
| `--model` | зависит от провайдера | имя модели |
| `--base-url` | — | адрес OpenAI-совместимого API / Ollama |
| `-o/--output` | `summary.md` | файл отчёта |
| `--json` | — | дополнительно сохранить JSON |
| `--lang` | `русский` | язык саммари |
| `--num-ctx` | 16384 | Ollama: контекст модели в токенах (`OLLAMA_NUM_CTX`) |
| `--chunk-chars` | 12000; для Ollama — по `--num-ctx` | размер фрагмента документа |
| `--context-chars` | 40000; для Ollama — по `--num-ctx` | объём текста в одном запросе на объединение |
| `--doc-words` | 250 | лимит слов на саммари документа |
| `--workers` | 4; для Ollama — 1 | параллельных запросов к LLM |
| `--ocr-lang` | `rus+eng` | языки Tesseract OCR |
| `--no-ocr` | — | не распознавать изображения и сканы |
| `--extract-only` | — | только извлечь текст и показать статистику |
| `--no-cache` | — | не кэшировать ответы LLM |

## Ограничения

- OCR распознаёт текст, но не «понимает» картинку: схемы, фото и графики без подписей
  дадут мало информации. Рукописный текст Tesseract читает плохо.
- Картинки, вставленные внутрь DOCX/PPTX, не распознаются — только отдельные файлы и сканы PDF.
- Старые `.doc/.xls/.ppt` не поддерживаются — нужно пересохранить в новый формат.
- `gdown` скачивает до 50 файлов на уровень папки. Для больших папок — Google Drive API
  или скачать папку архивом и передать путь к ZIP.

## Тесты

```bash
pip install -e ".[dev]" && pytest
```

Тесты покрывают извлечение всех форматов (включая cp1251, таблицы docx, ZIP, мусорные файлы,
битые файлы), нарезку, map-reduce и иерархическое сжатие, кэш, повторы при ошибках, CLI целиком,
провайдер Ollama на фейковом сервере (передача `num_ctx`, проверка модели, подбор размеров)
и OCR: настоящее распознавание картинок, повёрнутых сканов и кириллицы (если установлен Tesseract —
иначе эти тесты пропускаются), а также сборку текста страниц, пометки низкого качества и ошибки.
